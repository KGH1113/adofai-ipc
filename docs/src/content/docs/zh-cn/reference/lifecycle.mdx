## 类型验证

处理器执行前验证输入，返回后验证结果，均以契约为准。缺少必需字段、额外字段、未声明的 `null` 和枚举范围之外的字符串都会被拒绝。验证失败时返回调用错误，而不是正常结果。数组中的所有元素使用相同的规则检查。

- `int32`：−2,147,483,648 到 2,147,483,647 之间的整数。
- `safeint`：−9,007,199,254,740,991 到 9,007,199,254,740,991 之间的整数。C# 的 `long` 也必须处于该范围内。
- `float64`：有限的双精度数值，不允许 `NaN` 和 `Infinity`。

不会进行隐式类型转换，例如不接受用字符串 `"1"` 代替数值字段。类型映射以及省略与 null 的区别请参阅[契约定义](/docs/zh-cn/learn/contract/#共享类型)。

类型验证不能替代业务规则。正数约束、访问权限和算术溢出都需要在处理器中单独处理。

## 就绪与退出

- 模组：完成注册与初始化后调用 `MarkReady()`；停用时调用 `Dispose()`。
- 应用：`ready()` 等待模组就绪和应用注册响应；所属对象退出时调用 `dispose()`。
- 就绪后，单次调用仍可能因对端退出或执行错误而失败。不要复用已经释放的注册。

重连时，应用重新注册，`onStatus()` 报告 `ready`。此时重新查询快照，以补齐断线期间遗漏的状态。`appId` 在注册的生命周期内保持不变，而 `sessionId` 每次连接都会变化。模组获取的应用代理只属于对应会话，不要在新会话中复用已断开的代理。

## 取消与重试

C# 处理器通过 `context.CancellationToken` 检查取消。连接断开或模组注册释放时会取消该令牌，因此应将它传给任务和应用调用。

```csharp
context.CancellationToken.ThrowIfCancellationRequested();
```

长时间运行的任务可以通过契约中的独立方法取消，例如 `cancelJob(jobId)`。不能仅凭调用超时就判断长时间任务已经取消。

取消、超时和输出验证失败不会撤销已经发生的更改。如果结果返回前连接断开，可能无法确定请求是否执行，因此不要无条件重发修改请求。重连后应查询状态，或使用任务 ID 防止重复执行。SDK 不会自动重放请求。

## 线程与共享状态

必须在游戏线程上访问 Unity 对象。不要假设 `await` 之后仍在同一个线程上。耗时计算和文件处理应与游戏线程分离。

多个调用可能同时读取或修改共享状态。请保护必要的代码段，但不要在等待应用响应时持有锁。等待期间发生的状态变化需要由模组处理。
