`ipc`는 모드 진입점에서 얻은 `IIpcRuntime`입니다. 계약과 메서드 타입은 TypeSpec에서 생성합니다.

```csharp
using AdofaiIpc;
using AdofaiIpc.Loader;

var ipc = IpcLoader.GetRuntime(modsDirectory);
```

`modsDirectory`는 게임의 Mods 디렉터리입니다. 게임 스레드의 모드 활성화 콜백에서 호출하고 `AdofaiIpc.Contracts.dll`, `AdofaiIpc.Loader.dll`을 참조합니다. 생성 타입의 namespace도 `using`으로 가져옵니다.

## 등록과 메서드 구현

`RegisterMod()`로 계약을 등록하고 `Handle()`로 메서드를 구현합니다. 아래 예제의 계약은 `op echo(text: string): string;`입니다.

```csharp
using System.Threading.Tasks;

var mod = ipc.RegisterMod(
    EchoContract.Instance,
    displayName: "Echo",
    allowedOrigins: new[] { "http://localhost:5173" });

mod.Handle(EchoMethods.Echo, (request, context) =>
    Task.FromResult(request.Text));

mod.MarkReady();
```

| API·인자 | 설명 |
| --- | --- |
| `EchoContract.Instance` | 계약 ID와 메서드·타입을 포함한 생성 객체 |
| `displayName` | 모드의 표시 이름 |
| `allowedOrigins` | 접근을 허용할 브라우저 Origin 목록 |
| `Handle(method, handler)` | 생성된 메서드에 `Task<T>`, `void` 반환에는 `Task` handler 연결 |
| `MarkReady()` | handler 설치와 초기화 완료 후 호출 허용 |
| `MarkError(code, message)` | 등록을 오류 상태로 전환하고 새 호출 거절 |

`RegisterMod()`는 모드 등록 객체를 반환합니다. 같은 계약 ID를 동시에 중복 등록할 수 없습니다. 위 handler의 입력은 `EchoRequest`, `Text`는 `string`, 결과는 `Task<string>`입니다.

Origin은 scheme·host·port로 구분합니다. `http://localhost:5173`과 `http://localhost:4321`은 다릅니다. 허용 목록에는 페이지 경로를 넣지 않습니다.

## 요청한 앱 호출

`context.App`은 현재 요청을 보낸 앱입니다. `DialogsContract`에 등록한 `mod`에서 앱의 `confirm(message: string): boolean`을 호출하는 예제입니다.

```csharp
mod.Handle(DialogsMethods.RequestConfirmation, async (request, context) =>
{
    return await context.App.ConfirmAsync(
        new ConfirmRequest { Message = request.Message },
        context.CancellationToken);
});
```

`ConfirmAsync()`는 앱 handler의 결과를 `Task<bool>`로 반환합니다. 다른 탭이나 모든 앱을 호출하는 의미가 아닙니다. 대응하는 앱 구현은 [앱 API](/docs/reference/app/#앱-메서드-제공)를 참고하세요.

## 등록된 앱 선택

모드가 먼저 호출할 때는 `Apps`에서 현재 등록된 앱을 선택합니다. 다음 예제의 앱 메서드는 `notify(message: string): void;`입니다.

```csharp
var connectedApps = mod.Apps;

if (mod.TryGetApp(appId, out var target))
    await target.NotifyAsync(
        new NotifyRequest { Message = "작업 완료" }, cancellationToken);
```

`Apps`는 호출 시점의 목록 snapshot입니다. `TryGetApp()`은 UUID인 `appId`로 조회하며 없으면 `false`를 반환합니다. 목록을 얻은 뒤 연결이 종료될 수 있으므로 각 호출의 실패·취소를 처리해야 합니다. 실패한 앱 하나가 나머지 알림을 막지 않도록 전체 전송에서는 앱별로 오류를 처리합니다.

| 앱 API | 동작 |
| --- | --- |
| `AppConnected` / `AppDisconnected` | 앱 등록 완료 / 연결 종료 이벤트. 재연결 시 새 proxy 제공 |
| `AppEventFailed` | 이벤트 구독자에서 발생한 예외 전달 |
| `app.AppId` / `DisplayName` | 앱의 고정 등록 ID / 표시 이름 |
| `app.SessionId` | 현재 연결 세션 ID |
| `app.CancellationToken` | 연결 종료나 모드 해제 시 취소되는 토큰 |

이벤트는 `MarkReady()` 전에 연결합니다. `AppConnected`는 등록 응답을 보낸 뒤 발생하므로 초기 상태를 전달할 수 있습니다. 이벤트 인자는 `Action<TApp>`이므로 비동기 작업은 별도 함수·큐에서 실행하고 예외를 처리합니다. handler 안의 앱 호출에는 `context.CancellationToken`을 전달하면 현재 요청의 취소도 적용됩니다.

## 등록 해제

모드 비활성화 또는 unload 시 자신이 소유한 등록을 해제합니다.

```csharp
mod.Dispose();
```

다른 모드의 등록은 유지됩니다. 해제한 객체는 재사용하지 않고 재활성화 시 새로 등록합니다. 취소와 실행 스레드 조건은 [동작 규칙](/docs/reference/lifecycle/)을 참고하세요.
