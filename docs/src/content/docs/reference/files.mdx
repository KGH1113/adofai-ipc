---
title: 파일 전송
description: 계약에 파일을 선언하고 모드에서 앱으로 전송합니다.
---

`ipc.File`은 모드에서 앱으로 보내는 파일입니다. SDK가 실제 전송을 처리하며, 앱에서 읽기 전에는 본문을 전송하지 않습니다.

## 계약 정의

모드의 반환값이나 앱 메서드의 인자에 선언합니다.

```typespec title="main.tsp"
import "@adofai-ipc/typespec";

@ipc.mod("exports")
namespace Exports {
  op exportSettings(): ipc.File;

  @ipc.app interface Browser {
    receive(file: ipc.File): void;
  }
}
```

생성 후 C#은 `IpcFile`, TS는 `ReceivedFile`을 사용합니다. 모델의 필드·배열·nullable·optional에도 넣을 수 있습니다. 모드 인자나 앱 반환값을 통한 업로드는 허용하지 않습니다.

## 파일 반환

아래는 등록한 `mod`에서 파일을 반환하는 handler입니다.

```csharp
mod.Handle(ExportsMethods.ExportSettings, (request, context) =>
    Task.FromResult(IpcFile.FromPath(settingsPath, "application/json")));
```

| 생성 API | 인자·동작 |
| --- | --- |
| `FromPath(path, contentType)` | 읽을 파일 경로. 파일명과 크기를 자동으로 구합니다. |
| `FromStream(stream, byteLength, fileName, contentType)` | 현재 위치부터 읽을 스트림과 정확한 바이트 수. SDK에 소유권을 넘깁니다. |
| `FromWriter(writer, byteLength, fileName, contentType)` | 본문을 요청받았을 때 실행할 `Action<Stream>`. 지정한 길이만큼 씁니다. |

`contentType`의 기본값은 `application/octet-stream`입니다. 파일명은 제어 문자 없는 1–255자, 크기는 0부터 `safeint` 최댓값까지입니다. 보낸 `IpcFile`은 재사용하지 않으며, 반환 직후 `using`으로 닫지 않습니다. 보내지 않은 객체는 직접 `Dispose()`합니다.

## 앱에서 읽기

파일명·MIME 타입·크기는 읽기 전에도 사용할 수 있습니다.

```ts
const file = await channel.exportSettings();
console.log(file.name, file.type, file.size);

const settings = JSON.parse(await file.text());
```

| `ReceivedFile` API | 반환값 |
| --- | --- |
| `stream({ signal? })` | `ReadableStream<Uint8Array>`. 큰 파일은 스트림으로 처리합니다. |
| `text({ signal? })` | 전체 내용을 UTF-8로 읽는 `Promise<string>` |
| `arrayBuffer({ signal? })` | 전체 바이트의 `Promise<ArrayBuffer>` |
| `blob({ signal? })` | MIME 타입을 유지하는 `Promise<Blob>` |
| `download()` | 브라우저 기본 다운로드에 전달하는 `Promise<void>`. 전체 파일을 JS 메모리에 올리지 않습니다. |
| `open({ signal? })` | 원하는 위치를 여러 번 읽을 수 있게 연 `Promise<OpenedFile>`. [열어서 여러 번 읽기](#열어서-여러-번-읽기)를 참고합니다. |
| `used` | 읽기 API를 호출했는지 나타내는 `boolean` |

파일 하나는 한 번만 읽습니다. 다시 읽으려면 모드 메서드를 다시 호출합니다. `signal`은 파일 읽기를 취소하며, `text()`·`arrayBuffer()`·`blob()`은 전체 내용을 메모리에 올립니다.

## 브라우저에 저장

큰 녹화 파일 등을 저장할 때는 `download()`를 사용합니다. 계약과 C#의 `IpcFile` 제공 코드는 동일합니다.

```ts
const file = await channel.exportSettings();
await file.download();
```

SDK가 검증한 파일 정보를 이용해 브라우저에 다운로드 요청을 전달합니다. 앱은 티켓·URL을 다루거나
`blob()`으로 전체 본문을 먼저 읽지 않습니다. 저장 위치, 파일명 충돌, 진행 상태, 다운로드 취소는
브라우저가 관리합니다. 기본 다운로드 폴더 또는 저장 위치 확인 여부는 브라우저 설정을 따릅니다.

Promise는 **다운로드 요청을 브라우저에 전달하면** 완료됩니다. 파일 저장 완료나 HTTP 응답 성공을
보장하지 않으며, 브라우저가 요청을 차단하거나 네트워크 오류가 발생한 경우 앱이 이를 직접 관찰하지
못할 수 있습니다. 앱 handler에서 `await file.download()`를 반환해도 모드에는 저장 완료가 아닌
전달 완료만 알려집니다. 전송 중 IPC 연결을 유지해야 하며, 취소는 브라우저 다운로드 UI에서 합니다.

`download()`도 한 번 사용에 포함됩니다. 이후 같은 파일을 다시 읽거나 다운로드할 수 없습니다.
연결 종료·모드 비활성화 시 이전 파일은 무효가 되며, 다시 연결한 뒤 새 파일을 요청해야 합니다.
파일의 60초 시작 제한은 그대로 적용됩니다. DOM이 없는 환경에서는
`file_download_unavailable` 오류를 반환하며, 해당 환경에서는 `stream()`을 사용합니다.

## 열어서 여러 번 읽기

영상·오디오 미리보기처럼 같은 파일을 여러 번, 필요한 구간만 읽을 때는 `open()`을 사용합니다.
런타임 HTTP 서버가 파일 URL을 열고 HTTP Range 요청(206)을 받으므로, 전체 본문을 JS 메모리에
올리지 않습니다. 계약과 C# 코드는 그대로이며, 런타임 2.2.0 이상이 필요합니다.

```ts
const file = await channel.exportVideo();
const opened = await file.open();

video.src = opened.url; // 브라우저가 재생·탐색에 필요한 구간만 요청합니다.

const header = opened.read({ start: 0, end: 1024 }); // 0~1023번 바이트

await opened.close(); // 게임 쪽 파일 핸들을 해제합니다.
```

| `OpenedFile` API | 반환값 |
| --- | --- |
| `url` | `<video>`·`<audio>`·`<img>`·링크에 바로 쓸 수 있는 loopback URL |
| `name`·`type`·`size` | 받은 파일과 같은 파일명·MIME 타입·크기 |
| `read({ start?, end?, signal? })` | `start`부터 `end` 앞까지(`Blob.slice`와 같음) 읽는 `ReadableStream<Uint8Array>`. 여러 번 호출할 수 있습니다. |
| `close()` | 파일을 닫는 `Promise<void>`. 두 번 호출해도 됩니다. |
| `closed` | `close()`를 호출했는지 나타내는 `boolean` |

`open()`도 한 번 사용에 포함되지만, 실패하면 파일을 사용하지 않은 상태로 남깁니다. 이때는
`stream()`이나 `download()`로 대신 읽습니다. 탐색할 수 없는 소스(`FromWriter()`, 탐색할 수 없는
스트림)는 `file_not_seekable`로 거절하며, `FromPath()`와 탐색 가능한 `FromStream()`은 항상 열 수
있습니다. 런타임이 2.2.0보다 오래되었거나 파일이 만료되어 열 수 없으면 `file_open_unavailable`을 반환합니다.

연 파일은 `close()`를 호출하거나, 앱 세션이 끝나거나, 모드가 해제되거나, 30분 동안 아무 요청이 없으면
닫힙니다. 받은 파일의 60초 시작 제한은 `open()` 호출에 적용됩니다. URL의 토큰이 접근 권한이므로
`Origin`이 없는 미디어 요청도 허용하며, `Origin`이 있으면 모드가 허용한 출처인지 확인합니다.
응답은 `Content-Disposition: inline`과 `Content-Security-Policy: sandbox`를 붙여, HTML 같은 문서를
열어도 런타임 출처에서 스크립트가 실행되지 않습니다. 동시에 열 수 있는 파일은 64개입니다.

## 선택한 앱에 보내기

등록된 앱 proxy로도 같은 파일 타입을 보냅니다.

```csharp
if (mod.TryGetApp(appId, out var target))
    await target.ReceiveAsync(
        new ReceiveRequest { File = IpcFile.FromPath(exportPath) },
        cancellationToken);
```

```ts
app.use(ExportsContract, {
  receive: async ({ file }) => {
    await file.download();
  },
});
```

다운로드 저장·이미지 미리보기·오디오 재생 여부는 앱이 결정합니다. 앱 handler가 반환할 때까지
`ReceiveAsync()`가 기다립니다. 위 예제는 브라우저에 요청을 전달하면 반환합니다. 앱에서 본문 읽기
완료를 기다려야 한다면 `text()`·`arrayBuffer()` 또는 스트림 소비를 `await`합니다.

## 수명과 오류

받은 파일은 60초 안에 읽기 시작해야 합니다. 연결 종료·모드 해제·전송에 연결한 취소 토큰의 취소 시 사용할 수 없으며, 재연결 후에는 새 파일을 요청합니다. 전송 실패 시 SDK가 자동으로 다시 읽지 않습니다.

| 오류 코드 | 조건 |
| --- | --- |
| `file_expired` | 파일이 만료되었거나 이미 읽혀 사용할 수 없음 |
| `invalid_file` | 선언한 크기와 수신한 크기가 다름 |
| `file_transfer_failed` | 본문 전송 중 오류 |
| `file_transfer_unavailable` | 파일 전송을 지원하지 않는 런타임 |
| `file_download_unavailable` | 브라우저 다운로드를 제공하지 않는 실행 환경 |
| `file_not_seekable` | 탐색할 수 없는 소스라 `open()`할 수 없음. 파일은 그대로 남음 |
| `file_open_unavailable` | 2.2.0보다 오래된 런타임이거나 파일이 만료되어 `open()`할 수 없음. 파일은 그대로 남음 |
| `file_open_limit` | 이미 64개 파일이 열려 있음 |
| `file_closed` | 닫은 `OpenedFile`을 읽음 |

아직 읽지 않은 파일은 런타임 전체에서 최대 128개까지 유지합니다. 사용한 스트림과 만료된 파일은 SDK가 정리합니다. 파일 읽기는 게임 스레드에서 실행하지 않습니다.
