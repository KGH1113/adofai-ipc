---

모드·브라우저 앱·TypeSpec 계약은 같은 모노레포에서 관리하는 것을 권장합니다. 계약 변경과 양쪽 구현을 같은 PR에서 수정하고 검사할 수 있습니다.

## 디렉터리 구성

계약 원본과 생성 출력은 분리합니다.

```text
apps/
  mod/                  # C# 모드
    Generated/          # 생성된 *.g.cs
  web/                  # 브라우저 앱
packages/
  contracts/main.tsp    # 계약 원본
  ipc/                  # 생성된 TypeScript 패키지
```

같은 `.tsp`에서 양쪽 코드를 생성합니다. 출력에는 계약 객체, DTO, 호출 API와 입력·출력 검증 코드가 포함됩니다. 메서드의 실제 동작은 직접 구현합니다.

## 생성과 참조

Node.js 22 이상에서 `@adofai-ipc/typespec`을 개발 의존성으로 설치하고 루트에 출력 설정을 작성합니다.

```json title="adofai-ipc.config.json"
{
  "contract": "packages/contracts/main.tsp",
  "typescript": {
    "output": "packages/ipc",
    "packageName": "@example/ipc",
    "workspace": true
  },
  "csharp": {
    "output": "apps/mod/Generated",
    "namespace": "Example.Generated"
  }
}
```

```bash
pnpm exec adofai-ipc generate
pnpm exec adofai-ipc generate --check
```

`--check`는 파일을 바꾸지 않고 생성 결과가 다르면 실패합니다. 기존 생성 파일만 갱신·정리하며 수동 작성 파일은 별도로 보관합니다.

생성 패키지의 이름이 `@example/ipc`라면 앱 의존성에 연결합니다.

```json title="apps/web/package.json의 의존성 항목"
{
  "@example/ipc": "workspace:*"
}
```

pnpm workspace에 `apps/web`과 `packages/*`를 포함하고 루트에서 `pnpm install`을 실행합니다. 앱에는 `adofai-ipc` 런타임 의존성도 필요합니다. 생성 파일을 `node_modules` 안에서 직접 수정하지 않습니다.

## C# 참조와 검사

생성된 `*.g.cs`를 모드 프로젝트의 컴파일 대상에 포함합니다. 모드와 함께 컴파일하므로 생성물 전용 DLL은 필요하지 않습니다.

계약 변경 후 검사 순서는 다음과 같습니다.

```text
계약 검사 → 양쪽 코드 생성 → 앱 타입 검사·모드 빌드 → 호출 검증
```

생성 도구 버전과 출력 설정은 고정합니다. 생성물을 커밋한다면 CI에서 재생성 결과와 차이가 없는지도 확인합니다. 생성 파일은 수동으로 수정하지 않습니다.

모드와 앱의 계약 해시가 다르면 등록 시 `contract_mismatch`로 실패합니다. 변경한 계약에서 양쪽 코드를 생성해 함께 배포합니다.

## 모드와 앱의 저장소가 다를 때

계약 원본은 모드 저장소에서 관리합니다. C# 생성 코드는 모드에 포함하고, 같은 생성 결과의 TS 패키지를 웹 저장소의 `vendor/`에 복사해 커밋합니다.

```text
mod-repo/
  ipc/main.tsp
  ipc/generated/typescript/   # 웹에 전달할 생성 패키지
  src/Ipc/Generated/          # 모드가 컴파일할 C# 소스

web-repo/
  vendor/example-ipc/         # 고정한 TS 생성 패키지
  vendor/adofai-ipc/          # 고정한 SDK
```

출력 설정의 `workspace`를 제거하고 SDK 참조를 지정합니다. 이 예제는 웹의 두 vendor 폴더를 나란히 배치합니다.

```json title="adofai-ipc.config.json의 typescript 항목"
{
  "output": "ipc/generated/typescript",
  "packageName": "@example/ipc",
  "version": "1.0.0",
  "runtimeDependency": "file:../adofai-ipc"
}
```

```json title="웹 package.json의 의존성 항목"
{
  "adofai-ipc": "file:vendor/adofai-ipc",
  "@example/ipc": "file:vendor/example-ipc"
}
```

모드에서 생성·빌드한 뒤 TS 생성 패키지 전체를 웹에 갱신하고 설치·타입 검사를 실행합니다. 각 저장소는 자기 안의 파일과 잠금 파일만으로 빌드하며, CI에서 다른 저장소를 내려받지 않습니다. 전달한 생성 패키지의 계약 해시와 원본 커밋을 기록하면 버전을 추적할 수 있습니다.

생성 도구의 `version`과 `private` 옵션은 출력 패키지의 같은 항목을 설정합니다. npm 패키지로 배포한다면 `private: false`와 버전을 지정하고 웹에서 정확한 버전을 설치합니다. SDK 자체의 의존성도 함께 고정해야 합니다.
