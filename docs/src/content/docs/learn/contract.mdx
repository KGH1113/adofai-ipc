---

계약 파일에서 C#과 TypeScript API를 생성합니다. 메서드 이름과 입력·반환 타입을 양쪽에서 따로 작성하지 않습니다.

## 모드 메서드

`@ipc.mod` namespace가 등록의 진입점입니다. 루트의 `op`는 모드가 구현하고 앱이 호출합니다.

```typespec title="main.tsp"
import "@adofai-ipc/typespec";

@ipc.mod("echo")
namespace Echo {
  op echo(text: string): string;
}
```

- `"echo"`: 모드 계약의 고정 ID입니다. 표시 이름과 구분합니다.
- `Echo`: `EchoContract`, `EchoMethods`의 이름에 사용됩니다.
- `echo`: 문자열을 받아 문자열을 반환하는 메서드입니다.

앱은 `channel.echo({ text: "hello" })`로 호출하고, 모드는 `EchoMethods.Echo`에 handler를 등록합니다. 결과는 각각 `Promise<string>`과 `Task<string>`으로 처리합니다. 인자가 없으면 `ping()`처럼 호출합니다.

## 앱 메서드

같은 계약 안의 `@ipc.app` interface는 앱이 구현하고 모드가 호출합니다.

```typespec
import "@adofai-ipc/typespec";

@ipc.mod("dialogs")
namespace Dialogs {
  op requestConfirmation(message: string): boolean;

  @ipc.app
  interface Browser {
    confirm(message: string): boolean;
  }
}
```

위 계약에서 모드는 `requestConfirmation`, 앱은 `confirm`을 구현합니다. 역할은 interface 이름이 아닌 `@ipc.app`이 결정합니다. 앱 메서드가 필요 없으면 interface를 생략합니다.

## 공유 타입

구조화된 데이터는 `model`로 선언합니다.

```typespec
model ModInfo {
  displayName: string;
  revision: int32;
}
```

TypeScript에서는 `displayName: string`, `revision: number`가 되고, C#에서는 `string DisplayName`, `int Revision`이 됩니다. 이름 변환과 직렬화는 생성 코드가 처리합니다.

| TypeSpec | TypeScript | C# |
| --- | --- | --- |
| `string` / `boolean` | `string` / `boolean` | `string` / `bool` |
| `int32` | `number` | `int` |
| `float64` | `number` | `double` |
| `safeint` | `number` | `long` |
| `T[]` | `Array<T>` | `T[]` |
| `T \| null` | `T \| null` | `T?` |
| `field?: T` | `field?: T` | `IpcOptional<T>` |
| `"fixed"` / `"a" \| "b"` | 문자열 literal / literal union | 검증하는 `string` |
| 문자열 enum | 값 상수와 같은 이름의 union 타입 | 문자열로 직렬화하는 `enum` |
| `void` 반환값 | `Promise<void>` | `Task` handler |
| `ipc.File` | `ReceivedFile` | `IpcFile` |

`ipc.File`은 모드의 반환값과 앱 메서드의 인자에 사용합니다. 배열·nullable·optional 필드에도 넣을 수 있습니다. 전송 방법은 [파일 전송](/reference/files/)을 참고하세요.

## 생략과 null

`?`는 필드 생략을, `| null`은 명시적인 `null`을 허용합니다. 둘은 별도 조건입니다.

```typespec
model Patch {
  label?: string;
  note?: string | null;
}
```

```ts
const omitted: Patch = {};
const cleared: Patch = { note: null };
const changed: Patch = { label: "hello" };
```

```csharp
var omitted = new Patch();
var cleared = new Patch { Note = new IpcOptional<string?>(null) };
var changed = new Patch { Label = "hello" };

if (cleared.Note.IsSpecified)
    ApplyNote(cleared.Note.Value); // 여기서는 null
```

`IpcOptional<T>`의 기본값은 생략이며, 값이 있으면 `IsSpecified`가 `true`입니다. 생략된 필드의 `Value`는 읽지 않습니다. `label: null`은 이 계약에서 허용하지 않습니다.

## 문자열 enum과 반환값 없는 메서드

```typespec
enum Phase { Pending: "pending", Done: "done" }
op setPhase(phase: Phase): void;
```

```ts
import { Phase } from "@example/ipc";

await channel.setPhase({ phase: Phase.Done });
```

`Phase.Done`은 실제 값 `"done"`인 상수입니다. 같은 이름의 `Phase` 타입은 허용된 문자열만 받습니다. C#에서는 `Phase.Done` enum 값으로 전달하며 직렬화 값도 `"done"`입니다. `void`도 상대 handler가 완료되거나 실패할 때까지 기다립니다.

계약을 변경하면 양쪽 코드를 다시 생성해야 합니다. 출력 연결은 [코드 생성과 저장소 구성](/guides/monorepo/), 값의 제약은 [동작 규칙](/reference/lifecycle/)을 참고하세요.
