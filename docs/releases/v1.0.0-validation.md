# IPC v1 ecosystem validation

Validated on 2026-10-06 on macOS arm64 using the installed ADOFAI Unity/Mono runtime.
This is preparation evidence; no npm package, release tag or public release was published.

## Protocol and architecture

Product version 1.0.0 uses wire protocol 3, `/ipc/ws`, and `adofai-ipc.v3`.
Commands have IDs; named outcome events carry correlation IDs. Namespace lifecycle and domain
snapshots/changes are pushed. Consumers own their application ports, session state, correlation
and domain schemas; concrete SDK, Unity and native transports are injected at composition roots.
Payload field casing belongs to each domain schema. TUFReplay/Helper DTOs preserve PascalCase;
Impl uses explicit JsonProperty names, and Renderer uses its declared anonymous-object fields.

All five web/application vendor copies use the six canonical raw SDK files from clean upstream
commit `5b9b9a721ba526632bf14d01ceb9a2f641b31a4a`, their SHA256 manifests and the original MIT license.
No consumer requires a published adofai-ipc npm package.

## Verification

- IPC: run.sh check/build/client/package; SDK tests and real C# WebSocket interoperability.
  Protocol checks include hydration, named results, reverse commands, admission/deduplication,
  subscription/namespace/router cancellation, discarded dispatcher queues, authorization,
  validation details, single-use bounded streaming and late snapshot delivery after disconnect.
  Reverse commands, Origin violations and invalid namespace handles remain strict failures.
- TUFReplay render web: 203 tests, type checking, Biome and production build passed. Dev and
  webcam web/mod checks passed before integration. Native, Unity/Mono and C# mod suites passed.
- Renderer: mod-check/check/test/dmnote-check passed, including deterministic domain pulse
  expiry, previous-session cancellation isolation and local-peer recreation after IPC restart.
- Helper frontend: 14 tests and lint passed; staging build passed. Helper core/update suites
  and six bootstrap-install regressions passed; Release packaging and Debug install passed.
- Impl: C# 16 tests; frontend 135 tests plus two script tests; Rust lib/bin 39 tests each;
  strict clippy and frontend checks passed. Actual WKWebView fixture validated transparency,
  hand/foot rendering, tap/hold/mouse inputs, storage isolation and repeated-session pixels.
  The macOS application bundle was built and signature-verified.

Two actual-game smoke runs confirmed readiness of `adofai-ipc`, `tuf-replay`, `tufhelperlite`,
`impl-resourcepack` and `tuf-replay-renderer`; initial domain wire fields; correlated ping;
Renderer/DmNote protocol-2 attach acknowledgment and availability push; and peer disconnect
ownership cleanup. The final run also confirmed no IPC error or listener-shutdown fatal log.
The smoke did not start gameplay, downloads or a render job. Impl's temporary enable flag and
settings were restored to their exact original bytes, and the verification game was closed.

An existing TUFReplay automatic-update endpoint returned HTTP 404 during the smoke. This does
not prevent IPC readiness or messaging. Windows hardware capture and a complete movie-render
scenario were not exercised. shellcheck is unavailable; shell syntax checks passed.
