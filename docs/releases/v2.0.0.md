# ADOFAI-IPC 2.0.0

Consumer mods bundle Contracts, Loader and Runtime DLLs. The process owns one server, independent
of which consumer first starts it. Product version 2.0.0 keeps wire protocol 3 and introduces
contract major 1 with fixed assembly identity 1.0.0.0.

Removed the common UMM library mod, Info.json, automatic dependency installation, Bootstrap,
DependencyShim, runtime Shim, Launcher/updater, Migration, dependency dialogs, installer scripts,
update manifests and their obsolete tests. Historical v1 release notes describe removed behavior.

The local loader selects the highest compatible stable bundled runtime once, verifies manifest
and DLL metadata, and refuses hot replacement. Registration disposal releases only one feature.
The host stops on Unity application quitting/unloading. Consumers never receive a host Dispose API.

Validation commands:

```bash
./scripts/run.sh check
./scripts/run.sh build
./scripts/run.sh client
./scripts/run.sh package
```

Loader tests exercise separately compiled 2.0.0/2.1.0 fixture DLLs in fresh subprocesses:
highest version, distinct loader copies, concurrent calls, frozen selection, late requirements,
contract/wire mismatch, capability checks, malformed candidates, prerelease exclusion,
preloaded runtimes, duplicate contract identities and post-load failure retention.
Protocol tests exercise two registrations over a real WebSocket connection, disabling the first
without disconnecting the second, snapshot delivery, cancelled game-thread work, duplicate names,
configuration rollback, stale disposal, local peers and download revocation. Existing transport,
streaming and TypeScript tests remain applicable.

Actual ADOFAI/Unity Mono loading and application exit still require an in-game two-consumer test.
See the [bundling guide](../en/006-BundledRuntime.md). No public release or game installation is
performed by these commands.
