# ADOFAI-IPC v2 변경 및 검증

2026-10-11 기준 로컬 구현과 자동 검증 결과입니다. 공개 릴리즈는 수행하지 않았습니다.

## 구현 결과

각 소비 모드에 DLL을 동봉하고 게임 프로세스 공용 런타임에 기능을 등록하는 구조로 변경했습니다.
처음 서버를 시작한 모드를 끄더라도 다른 기능과 연결은 유지합니다.
모든 등록을 해제해도 서버는 유지하며 Unity application quitting/unloading 때 종료합니다.

기존 공용 라이브러리 모드의 Main 진입점과 Info.json, Bootstrap, DependencyShim, Shim,
Launcher/업데이터, Migration, 의존성 오류 대화상자, 자동설치 스크립트, update manifest,
관련 테스트 프로젝트를 제거했습니다. solution과 빌드·패키징 경로도 새 구조로 변경했습니다.
이전 릴리즈 문서는 과거 기록으로 남겨 두고 현재 한국어·영어 개발 가이드는 갱신했습니다.

## DLL과 버전 계약

| 구성 | 역할 |
| --- | --- |
| AdofaiIpc.Contracts.dll | 모드와 런타임의 안정적인 C# API. Unity·Newtonsoft.Json·모드 DTO 의존성 없음 |
| AdofaiIpc.Loader.dll | 동봉된 manifest와 DLL의 로컬 탐색·선택. 다운로드나 자동설치 없음 |
| AdofaiIpc.Runtime.dll | WebSocket 서버·라우터·기능 수명·Unity dispatcher |

제품 버전은 2.0.0, 계약 major는 1, Contracts/Loader의 AssemblyVersion은 1.0.0.0,
wire major는 3입니다. 기능별 메시지 major는 따로 선언하고 namespace 상태에 전달합니다.

로더는 호환 후보 중 가장 높은 안정 SemVer를 첫 시작 전에 선택합니다.
선택한 런타임은 게임 종료까지 고정하며 늦게 켠 모드의 최소 버전·major·capability 요구를 검사합니다.
호환성 실패는 기존 호스트를 종료하지 않습니다. DLL 로드 후 시작 실패는 재시작 전까지 유지하며
다른 버전으로 fallback하지 않습니다. 계약 어셈블리 중복 로드도 명시적으로 거부합니다.

모드는 IIpcRuntime.RegisterFeature로 등록하고 IFeatureRegistration.Dispose로 자기 기능만 해제합니다.
중복 이름은 거부하며 configure 예외는 해당 등록만 정리합니다.
기존 WebSocket 명령·상태 snapshot·취소·local peer·다운로드 스트리밍을 새 계약 어댑터로 연결했습니다.
dispatcher에는 최대 대기 1024개와 프레임당 실행 64개 제한을 두었습니다.

## 자동 검증 결과

- `./scripts/run.sh check`: shell syntax와 제품·계약·wire 버전 일치 검사 통과.
- `./scripts/run.sh build`: Debug DLL 빌드와 C# 테스트 통과.
- `./scripts/run.sh client`: TypeScript 빌드·타입 검사와 테스트 18개 통과. 실제 C# 서버 연동,
  서버 재시작과 페이지 재연결 시나리오를 포함합니다.
- `./scripts/run.sh package`: Release DLL 빌드·C# 테스트·ZIP 구조 검사 통과. ZIP에는 공용 모드의
  Info.json·shim·자동설치·업데이트 파일이 포함되지 않습니다.
- 로더 테스트 10개: 2.0.0/2.1.0 별도 DLL 선택, 로더 사본 통합, 동시 호출, 선택 고정,
  늦은 요구사항 실패, 계약/wire/capability 검사, 잘못된 manifest, prerelease 제외,
  선택 전 runtime 로드, 계약 중복, 로드 후 실패 고정.
- 실제 WebSocket으로 두 기능 등록·첫 기능 해제 후 두 번째 통신 유지·snapshot·대기 명령 취소·
  중복 등록 거부·configure rollback·오래된 등록 Dispose·local peer·다운로드 티켓 폐기를 확인했습니다.
- 기존 다운로드 테스트와 6 MiB 이상 UTF-8 스트리밍·Origin·correlation·재연결 테스트도 통과했습니다.

이 환경의 네트워크 제한 때문에 C# 검증 실행에는 `NuGetAudit=false` 환경 변수를 사용했습니다.
저장소의 NuGet 감사 설정은 변경하지 않았습니다. 실제 소켓 테스트는 로컬 포트 접근이 가능한
실행 환경에서 수행했습니다. 포함된 전송 코드의 obsolete API 경고는 남아 있습니다.
shellcheck가 설치돼 있지 않아 shell 검사는 bash 문법 검사로 수행했습니다.

기존 전송 코드의 비동기 delegate BeginInvoke/EndInvoke는 .NET 8에서 지원되지 않아
ThreadPool 호출로 변경했습니다. 정상 종료 중 완료된 read가 닫힌 stream을 접근하는 경우도
처리했습니다. 변경 이유는 transport/PATCHES.md에 기록했습니다.

## 배포 산출물

로컬 `.env`의 기존 경로 설정에 따라 `build/AdofaiIpc.zip`과 `.sha256`을 생성했습니다.
ZIP을 소비 모드 루트에 펼치면 다음 배치가 됩니다.

```text
ExampleMod/
  ExampleMod.dll                    # 소비 모드 자체
  Info.json                         # 소비 모드 자체
  AdofaiIpc.Contracts.dll
  AdofaiIpc.Loader.dll
  ipc/
    AdofaiIpc.Runtime.dll
    manifest.json
```

소비 모드는 Contracts/Loader만 참조하고 Runtime을 직접 참조하지 않습니다.
게임 폴더에 설치하거나 외부에 게시하지 않았습니다.

## 실제 게임에서 남은 검증

자동 테스트는 .NET 8에서 실행했습니다. ADOFAI를 실행해 native Unity/Mono의 DLL 로딩을
검증한 것은 아닙니다. 실제 UnityEngine.CoreModule을 ilspycmd로 확인해 application
quitting/unloading 이벤트가 제공되는 것은 확인했습니다.

릴리즈 전에는 서로 다른 버전을 동봉한 소비 모드 두 개로 게임에서 다음을 확인해야 합니다.

1. UMM이 루트 Contracts/Loader 참조를 같은 계약 Assembly 인스턴스로 해석하는지 확인.
2. 로드 순서를 바꿔도 최신 호환 런타임 하나를 선택하는지 확인.
3. 첫 소비 모드를 끄고 다시 켜도 다른 모드의 연결이 유지되는지 확인.
4. Unity 게임 스레드에서 시작하고 application 종료 때 호스트가 정리되는지 확인.

이 검증을 마치기 전에는 실제 게임 호환성을 확정한 릴리즈로 취급하지 않습니다.
