# AdofaiIpc 0.4.2

Final standalone transition release for TUFHelperLite 1.0.0 and TUFReplay 1.0.0.
Both mods now carry their SDK and migrate existing installations automatically
using their original public ZIP names.

The 0.4.2 package retains the genuine standalone Shim, Launcher, Bootstrap and
runtime layout accepted by existing installers and automatic updaters. The
runtime remains loaded for the current session. After the old updater call
stack has returned and both installed consumers have their SDK and direct
entry point on disk, it removes `Mods/AdofaiIpc` in the running game. There is no
modal, restart prompt, forced restart or exit-time deletion helper. If a
consumer is still on the old entry point, the legacy installation is retained.

Removal first detaches the directory outside `Mods`, then immediately deletes
its contents. File locks may leave detached bytes in `.adofai-ipc-retired`;
consumer launchers retry those leftovers on a subsequent startup. The actual
Windows game/Mono file-lock behavior must be checked manually. A directory
that cannot be detached is preserved and the failure is logged.

Keep this release as GitHub Latest. Future SDK releases must use
`make_latest: false`, or carry these unchanged legacy ZIP/checksum/manifest
assets so old `releases/latest/download/AdofaiIpc.*` URLs remain valid. The SDK
is not installed as a standalone `AdofaiIpc.zip` replacement.

Validation covers the normal build/package suites, offline/incomplete consumer
retention, immediate filesystem removal with settings/data preservation, wrong
identity and link refusal. These checks do not claim Unity/Windows E2E success.
