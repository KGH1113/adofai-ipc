## 타입 검증

입력은 handler 실행 전에, 결과는 반환 후에 계약으로 검증합니다. 필수 필드 누락·추가 필드·선언하지 않은 `null`·enum 밖 문자열은 거절합니다. 실패하면 정상 결과 대신 호출 오류로 전달합니다. 배열은 모든 원소를 같은 조건으로 검사합니다.

- `int32`: −2,147,483,648부터 2,147,483,647까지의 정수.
- `safeint`: −9,007,199,254,740,991부터 9,007,199,254,740,991까지의 정수. C# `long`도 이 범위 안이어야 합니다.
- `float64`: 유한한 배정밀도 숫자. `NaN`·`Infinity`는 허용하지 않습니다.

숫자 필드의 문자열 `"1"`처럼 암묵적인 타입 변환은 하지 않습니다. 타입 매핑과 생략·null의 구분은 [계약 정의](/learn/contract/#공유-타입)를 참고하세요.

형식 검증은 업무 규칙을 대신하지 않습니다. 양수 제한, 접근 권한과 연산 overflow는 handler에서 별도로 처리해야 합니다.

## 준비 상태와 종료

- 모드: 등록과 초기화 후 `MarkReady()`를 호출합니다. 비활성화 시 `Dispose()`로 해제합니다.
- 앱: `ready()`는 모드 준비와 앱 등록 응답까지 기다립니다. 소유자의 종료 시 `dispose()`를 호출합니다.
- 준비 완료 이후에도 상대의 종료나 실행 오류로 개별 호출이 실패할 수 있습니다. 해제한 등록은 재사용하지 않습니다.

재연결하면 앱을 다시 등록하고 `onStatus()`에 `ready`를 전달합니다. 이때 snapshot을 다시 조회해 연결 중 놓친 상태를 보완합니다. `appId`는 등록 수명 동안 유지하지만 `sessionId`는 연결마다 달라집니다. 모드에서 얻은 앱 proxy는 해당 세션에만 연결되며, 끊긴 proxy를 새 세션에 재사용하지 않습니다.

## 취소와 재시도

C# handler는 `context.CancellationToken`으로 취소를 확인합니다. 연결 종료·모드 해제 시 취소되므로 작업과 앱 호출에 토큰을 전달합니다.

```csharp
context.CancellationToken.ThrowIfCancellationRequested();
```

장기 작업의 취소는 `cancelJob(jobId)`처럼 계약의 메서드로 별도 제공할 수 있습니다. 호출 시간 제한만으로 장기 작업을 취소했다고 판단하지 않습니다.

취소·시간 제한·출력 검증 실패는 이미 수행한 변경을 되돌리지 않습니다. 결과 수신 전에 연결이 끊기면 실행 여부가 불명확할 수 있으므로 변경 요청을 무조건 다시 보내지 마세요. 재연결 후 상태를 조회하거나 작업 ID로 중복 실행을 방지합니다. SDK는 요청을 자동 재실행하지 않습니다.

## 스레드와 공유 상태

Unity 객체는 게임 스레드에서 접근해야 합니다. `await` 이후에도 같은 스레드라고 가정하지 마세요. 긴 계산과 파일 처리는 게임 스레드를 점유하지 않도록 분리합니다.

여러 호출이 공유 상태를 읽고 수정할 수 있습니다. 필요한 구간을 보호하되 앱 응답을 기다리는 동안 잠금을 유지하지 않습니다. 대기 중 발생한 상태 변경은 모드에서 처리해야 합니다.
